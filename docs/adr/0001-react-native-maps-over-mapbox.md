# ADR-0001: 地図ライブラリはreact-native-mapsとし、WebのMapboxとは統一しない

## ステータス

承認済み

## コンテキスト

本アプリの中核機能は近傍スポット検索(現在地周辺に約1,900件の車中泊スポットをマーカー表示し、タップでWebの詳細ページへ誘導)である。Web(車旅のしおり)は地図にMapboxを使用しており、モバイルでも統一するかが論点だった。

候補は3つ:

- **react-native-maps**: iOS=Apple Maps / Android=Google Maps。ネイティブ地図SDKのため表示コストは完全無料・MAU制限なし。最も実績があり、クラスタリングも定番ライブラリで対応可能
- **expo-maps**: Expo公式だが比較的新しく、iOSの最低バージョン要件が高い(iOS 17+)。獲得アプリとして対象ユーザーを狭めるリスクがある
- **@rnmapbox/maps**: Webと地図スタイルを統一でき、クラスタリング組み込み。ただし無料枠は月間25,000 MAUまでで、シークレットのダウンロードトークン管理・課金設定が必要

## 決定

react-native-mapsを採用する。WebのMapboxとの地図スタイル統一は行わない。

## 理由

- 本アプリは無料の獲得用ファネルであり、地図表示に従量課金リスク(Mapboxの25,000 MAU超過)やトークン運用の手間を背負う理由がない
- 用途は「マーカー表示してタップでWebへ誘導」のみで、カスタム地図スタイルの機能的価値がない。Webとの見た目の統一は誘導ファネルの成果に寄与しない
- OSネイティブの地図(Apple Maps / Google Maps)の見た目は、むしろ「薄いアプリ」の性格に合う

## トレードオフ

- Webと地図の見た目が異なる。ブランド統一感は劣るが、許容する
- iOSとAndroidで地図の見た目・挙動が異なる(Apple Maps / Google Maps)。プラットフォームごとの微調整が必要になる場合がある
- AndroidではGoogle Maps APIキーの設定が必要(ネイティブSDKの地図表示は無課金)

## 注意

将来、Webと共通のカスタム地図スタイルやベクタタイル配信が本当に必要になった場合のみ、Mapbox移行を再検討する。その際は無料枠(MAU)と当時のアクティブユーザー数を必ず突き合わせること。
