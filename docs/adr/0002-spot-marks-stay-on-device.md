# ADR-0002: スポットの印は端末内だけに保存し、計測にも場所を含めない

## ステータス

承認済み

## コンテキスト

一度使った人に戻ってきてもらうため、[スポットの印](../../CONTEXT.md)(なし／行きたい／行った／また行きたい)を導入する。成果地点は引き続きWeb誘導であり、印は再訪とWeb誘導を増やす手段と位置づける。

論点は2つあった。

1. **印をどこに保存するか。** 候補は、端末内(AsyncStorage)のみ／tns-webのサーバーに保存して同期。
2. **印の計測(PostHog)にどのスポットかを含めるか。** 「行った」はその場所で夜を過ごしたことを意味し、端末IDに `spot_id` が並ぶと車中泊した場所の履歴になる。

前提:

- アプリにはログインがなく、端末を識別するのはPostHogの匿名の端末IDだけである
- tns-webはVercel Hobbyの無料枠でCPUを節約しており、アプリからの新しいサーバー呼び出しは増やさない方針
- `/api/v1/spots` は公開の取り決め(tns-web ADR-0006)で、書き込み系を足すと取り決めの見直しになる
- 既存の `spot_card_opened` / `spot_web_referral` はすでに `spot_id`・都道府県・丸めた距離を送っている

## 決定

### 保存

- 印はAsyncStorageで端末内だけに保存し、サーバーには送らない
- アンインストールや機種変更で消えることを許容し、そのことを利用者に一言伝える(「引き継がれる」とは書かない。Androidの自動バックアップは確実ではないため)
- 印の書き出し・読み込みはMVPに入れない。1人あたりの印の数を計測で見て、必要になったら検討する
- APIからスポットが消えても印のデータは消さず、表示しないだけにする

### 計測

- `spot_mark_changed` には `from`・`to`・`origin`・`spot_type` と、その時点の状態ごとの件数(行きたい・行った・また行きたい)だけを送る
- `spot_id`・都道府県・距離は送らない
- 既存のスポット系イベント(`spot_card_opened`・`spot_web_referral`)に、そのスポットの印の状態を足さない。足すと、すでに送っている `spot_id` と組み合わさり、行った場所が分かってしまうため

## 理由

- 端末内に保存すれば、サーバーのCPU・費用も公開APIの取り決めも変わらない。ログインのないアプリで同期を作るには認証の仕組みから必要になり、MVPとして重すぎる
- 効果の判断(印を使う人の割合、1人あたりの件数、印を付けた人の再訪とWeb誘導、「行きたい」が「行った」に変わった回数)には、どのスポットかは要らない
- PostHogの公式ドキュメント自体が、ずっと変わらない端末IDを個人データとみなされ得るものとしている。IPアドレスなどを削っても、同じ端末IDの下に行った場所が並べば履歴として残るため、「匿名だから送ってよい」とはならない
- 場所を送らないので、アプリ用プライバシーポリシー(tns-web `/privacy/app`)の更新は不要。印を付ける操作は、既存の記載「リンクのタップなどの操作」の範囲に収まる

## トレードオフ

- 機種変更などで印が消える。「貯まる楽しさ」を狙う機能としては弱点になる
- 「行きたい」として人気のスポットや、「行った」が多い地域は分からない。tns-webでどのスポットのデータを優先して直すかの材料には使えない
- 地図のスポットカードから印を付けた場合、直前の `spot_card_opened`(`spot_id` あり)と送った順番から、どのスポットかを推測できてしまう。この決定は「1つのイベントだけで場所の履歴が読める形では残さない」ところまでで、完全に隠すものではないと承知している

## 注意

- 同期を追加する場合は、端末に貯まった印をサーバーへ移す手順が必要になる。そのときの利用者数とVercelの無料枠を突き合わせること
- 人気のスポットを知りたくなった場合は、印のイベントを端末IDと切り離して送る方法(送るたびに使い捨てのIDにするなど)を検討する。その際は、SDKで実現できるかの確認、IPアドレスを記録しない設定、プライバシーポリシーへの追記をあわせて行う
- 「行った」を付けた直後に現地報告を案内する機能(MVP外)を作る場合、案内を表示したイベントには `spot_id` を含めない(「行った」を付けた全員に発生し、行った場所の履歴と同じになるため)。案内から現地報告を開いたときは、既存の `spot_web_referral` に専用の `origin` を付けて `spot_id` ありで送ってよい。開くのは公開するつもりの人だけで、投稿すればtns-web側にもスポットと投稿者が保存されるため、新たに漏れる情報はほとんど増えない(tns-web ADR-0011が管理者を脅威の対象外とするのと同じ立場)
- 印とは別に、PostHogのプロジェクト設定「IP data capture configuration」でIPアドレスを記録しない設定にすることを推奨する(運用上の作業)
